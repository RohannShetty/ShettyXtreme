# Section 19 — Risks & Failure Modes

Single-operator trading software has a special property: failures are both technical and financial, and there is no team to catch them. This section is the operator's personal risk register. Every mode names its trigger, impact, detection, and mitigation; the highest-severity modes get explicit watch rules. The mitigation discipline is carried in [Section 18 — Repo & Codebase Strategy](18-repo-codebase-strategy.md) (boundaries), [Section 17 — Delivery Roadmap](17-delivery-roadmap.md) (gates), and [Section 11 — Dhan Integration](11-dhan-integration.md) (broker resilience).

| Failure mode | Trigger | Impact | Detection | Mitigation |
|---|---|---|---|---|
| **Overbuilding** | Building features before the pipeline earns its keep | Months lost; complexity drowns the operator | Feature map drift; code churn without test growth | Feature-map discipline ([Section 08](08-feature-map.md)); phase gates: no phase N+1 before phase N exits; seductive-distraction list reviewed each phase |
| **Duplicate infrastructure** | Rewriting what DhanHQ-py or the vendor zone already provides | Two implementations, two bug sets, drift | Two adapters/caches for the same capability | DhanHQ-py 2.2.0 is the only runtime pip dep (per D1); vendor contract (`FILES.yaml` + no-import gate, per D7); adapt, don't reimplement ([Section 10](10-openalgo-utilization.md)) |
| **Tight coupling to upstream** | Auto-adopting OpenAlgo or DhanHQ-py changes | Silent breakage; vendor lock | Release notes unread; syncs unattended | Anti-corruption layer (`core/interfaces` protocols); monthly diff-review cadence (per D1, corrected fact 3: ~3 releases/mo); DhanHQ-py stays pinned 2.2.0 while 2.3.0rc1 is diffed, never auto-upgraded (corrected fact 5); changelog-driven review per [Section 07 — Update-Resilient Design](07-update-resilient-design.md) |
| **Poor boundary design** | One layer importing another's internals | God modules; knowledge contaminating decisions; impossible test targeting | Import-rule grep drift | CI import gates: core zero-external, intelligence core-only, knowledge core-only (D12); 500-line rule; ADR-gated core changes |
| **Latency assumptions** | Assuming tick→screen latency that the stack doesn't deliver | Stale decisions, slippage, false signals | No latency metrics in observability | Single local process (no network hops inside the pipeline); WS feed design with correct codes 15/17/21 (corrected fact 2); feed staleness indicators; measure from Phase 2, design around reality |
| **Broker brittleness** | Dhan WS drops, token expiry, entitlement gaps | Frozen data, missed exits, failed orders | No health checks; 806 treated as credential error | Fail-closed trading (order path halts on any trading-side doubt); staleness indicators; watchdog reconnect; `data_access_token` fallback slot (per D8); 806 surfaced as "subscribe to Data APIs" entitlement message (corrected fact 1) |
| **UI complexity** | Terminal grows past what one operator can scan | Decision blindness in the cockpit | DESIGN.md violations; panel sprawl | DESIGN.md is the contract (per D4): 9 sections, progressive disclosure, keyboard-first ([Section 15](15-design-system-terminal-ux.md)); Svelte components; compliance pass in Phase 2; no panel added without a DESIGN.md change |
| **Signal overfitting** | Heuristics tuned on the last 20 sessions | Edge that exists only in the backtest | No shadow logs; calibration curve absent | Shadow models for all new voters (≥20 sessions before activation, per [Section 06](06-proposed-architecture.md)); honest walkforward (option premium + exit policy, not underlying % moves); voter-correlation block caps (Phase 3); cost-aware EV rejects marginal strategies by construction ([Section 16](16-monetization-business.md)) |
| **Operational fragility** | Restart loses session state; kill switch unreachable | Untracked risk mid-session | Mode file env-dependent (the `test_execution_mode_default` failure) | OBSERVER default with explicit per-session LIVE confirmation (per D10); session state persisted to DB; file-based kill switch independent of platform; health checks per subsystem |
| **Maintainability collapse** | Files grow past one operator's working memory | Bugs hide; every change regresses something | Files >500 lines; review gates skipped | 500-line CI rule; review gates on every merge; ledger for outcomes; core changes ADR-gated; per-module test dirs keep the suite runnable |
| **Knowledge-layer contamination** | Ingested content influencing live decisions | Unvalidated ideas traded as edge | Knowledge imports intelligence | D12 physical separation: `knowledge/` imports `core/` only, can never import `intelligence/` or `execution/`; human approval gate on every activation |
| **False-confidence forecasting** | Presenting predictions as certainty | Oversized positions on noise | Confidence without calibration | Probabilistic framing everywhere ("conditions X precede Y with probability P"); conviction + disagreement + participation visible; calibration curve ties confidence to realized win rates (Phase 3) |

## Watch rules (highest severity)

1. **Overbuilding**: if a feature is not on the [Section 08 — Feature Map](08-feature-map.md) row for the current phase, it is not built this phase. This rule has no exceptions, including "just a small script."
2. **Broker brittleness**: the trading path fails closed. When in doubt about Dhan session health, the platform refuses orders and says why — never guesses.
3. **Signal overfitting**: nothing graduates from shadow without the recorded data behind it. The ≥20-session gate is a floor, not a suggestion.
4. **Boundary drift**: the import-rule greps are part of every merge gate. A one-line boundary violation is a rejected merge, not a TODO.

The register is re-audited at each phase exit ([Section 17](17-delivery-roadmap.md)); a failure mode that produced an incident earns a remediation item in the next phase's scope, not a footnote.
