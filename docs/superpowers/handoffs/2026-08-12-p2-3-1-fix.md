## Summary

Implemented all 11 opportunity scanner types as specified in P2-3.1. The scanner architecture now follows a two-cadence model:

- **Tier A (event-driven):** GapFillScanner, VolumeAnomalyScanner, OIBuildupScanner — subscribe to `MARKET_DATA_BAR` and emit findings in real-time
- **Tier B (snapshot-driven):** GammaSpikeScanner, IVCrushScanner, IVExpansionScanner, PCRExtremesScanner, MaxPainDriftScanner, ThetaHarvestScanner, CalendarSpreadScanner, VerticalSkewScanner — called by the chain poller after each chain refresh

All scanners emit `SCANNER_FINDING` events on the EventBus. A new `ScannerProjection` stores capped per-type finding lists. The `/api/scanner/findings` endpoint serves findings with optional `?scanner_type=` filter. Frontend `ScannerPanel.svelte` displays findings grouped by scanner type.

## Known Limitations

1. **VIX feed:** INDIAVIX resolvability via instrument master unverified. Scanner uses ATM-IV proxy fallback.
2. **Earnings calendar:** No real calendar. Uses DTE ≤ 2 proxy with `catalyst_known=false`.
3. **Chain coverage:** Tier B scanners need chain data fed via `scan_chain()`/`scan()` methods. Chain poller task not yet wired in lifespan (requires data_adapter).
4. **Gamma history:** In-memory only, lost on restart. Needs 2+ observations before firing.
