# P3-4.3 Handoff — Order Detail Visibility

**Date:** 2026-08-12 · **Status:** Complete — all tests pass

## Summary

Fixed the order detail visibility gap: proposals now carry full leg detail (strike, expiry, CE/PE, lot size, premium, SL, target, rationale, confidence, EV, strategy, underlying) from the moment they are created, positions carry trade context from their originating proposal, and an order history tab is available in the right dock.

## Root Cause

The production `ExecutionSignalBridge` was wired with the **default (minimal) hint builder**, which produces bare `NIFTY` + qty + MARKET + MIS and no strike/expiry/option_type/SL/target/rationale. The full-detail **chain hint builder already existed** but was never wired into `app.py`.

## What Changed

### A. Wire `make_chain_hint_builder` (biggest lever)

**`terminal/api/app.py`** — Lines 523–557 (bridge wiring):
- Created `_chain_provider` (reads `app.state.options_chain` cache) and `_spot_provider` (reads watchlist LTP cache) as sync callables
- Wired `make_chain_hint_builder(instrument_master, chain_provider, spot_provider)` as the `hint_builder` parameter to `ExecutionSignalBridge`
- Proposals are now born with full detail when chain data is available; gracefully falls back to default hint when chain/spot are unavailable

### B. Enrich proposal payload end-to-end

**`terminal/api/models.py`** — `ProposalResponse`:
- Added `confidence`, `ev_after_cost`, `strategy`, `underlying` fields (all optional, default None)

**`terminal/api/execution_router.py`** — `_proposal_response()`:
- Maps `hint.get("confidence")`, `hint.get("ev_after_cost")`, `hint.get("strategy")`, `hint.get("underlying")` through

**`execution/signal_bridge.py`** — `make_chain_hint_builder`:
- Added `"strategy"` and `"underlying"` to the hint dict output
- Default hint builder also includes `"strategy": "stand_aside"` and `"underlying"` for consistency

### C. Make proposal card the full order ticket

**`terminal/web/src/lib/api.ts`** — `Proposal` type:
- Added `confidence`, `ev_after_cost`, `strategy`, `underlying` fields

**`terminal/web/src/components/ProposalQueue.svelte`**:
- Card line2: renders CONF (confidence %) and EV (after cost, colored up/down) inline
- Rationale: no longer 80-char truncated — displays full text with 2-line CSS clamp + hover tooltip
- Confirm dialog: added CONFIDENCE, EV AFTER COST, STRATEGY rows

### D. Link positions back to their plan

**`core/data_models/orders.py`**:
- `OrderRequest`: added `stop_loss`, `target`, `rationale`, `confidence`, `signal_id` fields
- `Order`: added `strike`, `expiry`, `option_type`, `lot_size`, `stop_loss`, `target`, `rationale`, `confidence`, `signal_id` fields

**`execution/execution_engine.py`** — `_build_order()`:
- Passes `stop_loss`, `target`, `rationale`, `confidence` from strategy hint to OrderRequest
- `approve()`: sets `order.signal_id = approval.signal_id`

**`execution/mode_router.py`** — `_place_paper()`:
- Passes all new OrderRequest fields through to paper engine

**`execution/paper_trading.py`** — `place_order()`:
- Accepts optional `strike`, `expiry`, `option_type`, `lot_size`, `stop_loss`, `target`, `rationale`, `confidence`, `signal_id` kwargs
- Stores them on the `Order` record
- `_fill_order()`: POSITION_CHANGED event now includes `signal_id`, `stop_loss`, `target`, `rationale`, `confidence`, `lot_size` when present

**`terminal/projections.py`** — `PositionProjection`:
- `on_position_update()`: merges `signal_id`, `stop_loss`, `target`, `rationale`, `confidence`, `lot_size` from fill event into position dict

### E. Render position identity + plan

**`terminal/api/models.py`** — `PositionResponse`:
- Added `stop_loss`, `target`, `rationale`, `confidence`, `signal_id`, `lot_size` fields

**`terminal/api/execution_router.py`** — `_enrich_position()`:
- Maps `raw.get("stop_loss")`, `raw.get("target")`, etc. through to PositionResponse

**`terminal/web/src/components/PositionsRiskStrip.svelte`**:
- Added Strike, Type (CE/PE colored), Expiry columns to the positions table
- Position type includes `stop_loss`, `target`, `rationale`, `confidence`, `signal_id`, `lot_size` (data from API)

**`terminal/web/src/components/GreeksPanel.svelte`**:
- Added Strike, Type (CE/PE colored), Expiry columns to the per-position greeks table

### F. Add order history

**`terminal/api/models.py`** — `OrderResponse`:
- New model: `order_id`, `symbol`, `exchange`, `side`, `order_type`, `quantity`, `price`, `status`, `filled_quantity`, `average_price`, `tag`, `created_at`, `strike`, `expiry`, `option_type`, `lot_size`, `stop_loss`, `target`, `rationale`, `confidence`

**`terminal/api/execution_router.py`**:
- `_order_response()` serializer
- `GET /api/execution/orders` endpoint with optional `status` filter, newest-first

**`terminal/web/src/lib/api.ts`**:
- `OrderRecord` type
- `getOrders()` function

**`terminal/web/src/components/OrderHistory.svelte`** (new):
- Full order history panel: filter bar (ALL/FILLED/REJECTED/CANCELLED/OPEN), order cards with symbol + strike + CE/PE + expiry + side + status badges, QTY/FILLED/PRICE/TYPE + SL/TGT + rationale

**`terminal/web/src/components/RightDockTabs.svelte`**:
- Added "Orders" tab between Proposals and Research
