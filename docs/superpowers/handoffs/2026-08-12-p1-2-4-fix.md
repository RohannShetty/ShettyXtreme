# P1-2.4 Fix: UI State Confusion — Connected / Disconnected / Open

**Date:** 2026-08-12
**Status:** Complete
**Verification:** 1315 tests passed, `npm run check` 0 errors, `npm run build` OK

## Summary

Replaced three independent, contradictory status widgets with a single state machine (`ConnectionState` enum) that serves as the canonical connection status across backend and frontend.

## State Machine

```
DISCONNECTED → CONNECTING → CONNECTED → STALE → EXPIRED → DISCONNECTED
```

Priority (highest first): EXPIRED > DISCONNECTED > CONNECTING > STALE > CONNECTED.

## What Changed for the Operator

- **Before:** Connection pip said DISCONNECTED (data socket down) while cred chip said CONNECTED (token valid). No CONNECTING state. STALE was dead code. Health was pull-only (30s poll).
- **After:** Single `state` value drives the pip. CONNECTING visible during reconnect. STALE reachable via tick-based detection. Server pushes transitions via WebSocket. Browser WS drops visibly degrade the pip instead of silently freezing the LTP hero.
