## Architecture Decisions

1. **IV cache bridging**: The chain poll and position poll are independent REST
   endpoints. A module-level `_iv_cache` dict in `execution_router.py` bridges
   them: the intelligence router populates it on each chain enrichment; the
   execution router reads it on each positions request. This avoids coupling
   the two endpoints or requiring a shared state object.

2. **No tick-driven recompute**: IV is absent from the HSM tick feed, so greeks
   cannot be computed per-tick. The 15s REST poll is the natural refresh
   cadence — consistent with how IV already refreshes in ChainGrid.

3. **Option identity via `from_fyers()`**: Position symbols are Fyers-format
   (e.g. `NSE:NIFTY26AUG25000CE`). The existing `from_fyers()` parser
   extracts strike/option_type/expiry. Non-option positions (indexes, equities)
   get `None` for all three fields and no greeks.

4. **QuantLib declared but not enabled**: `QuantLib>=1.43` is now in
   `pyproject.toml` under `[project.optional-dependencies] quantlib`. The
   config flag `use_quantlib: false` in `default.yaml` keeps the pure-Python
   Black-76 path as default. The hardcode at `intelligence_router.py:287`
   remains for now (config integration is a follow-up).

5. **rho omitted from display**: Both engines compute rho but `OptionsChainItem`
   has no rho field. The findings doc noted this; rho is low-signal for Indian
   index options (rates barely move). Left for a future addition if needed.

## What's Next (P2-3.3 — Risk Heatmap)

The GreeksPanel now provides the per-strike and portfolio greeks data needed
for the risk heatmap. Key hooks:
- `/api/execution/portfolio-greeks` returns per-position greeks with
  strike/option_type/expiry — the heatmap can aggregate by strike or expiry
- The IV cache (`_iv_cache`) provides strike-level IV data for heatmap coloring
- `GreeksPanel.svelte` can serve as the data source or the heatmap can poll
  the same endpoint directly
