**Date:** 2026-08-12

## Summary

Implemented expiry calendar intelligence for ShettyXtreme. The instrument master now exposes distinct expiry dates per underlying, classified as weekly/monthly via a per-symbol policy table. A new `/api/intelligence/expiry-calendar` endpoint serves structured calendar data. The frontend ChainGrid dropdown now fetches the full calendar on symbol change instead of passively learning expiries. Backend default resolution replaces the opaque "Fyers picks nearest" behavior.

## Key Design Decisions

1. **Policy table over pure heuristic**: `_EXPIRY_POLICY` in `symbols.py` explicitly encodes per-underlying weekly-day rules (BANKNIFTY Mon-Thu, NIFTY Thu, MIDCPNIFTY Mon) + monthly anchor (last Thu). More testable and accurate than `is_monthly_expiry()` alone.

2. **Server-side default resolution**: When `expiry` is empty, `/options` now resolves the calendar default before calling the adapter. Index → nearest weekly, stock → nearest monthly. Eliminates the opaque "Fyers picks nearest" behavior.

3. **Frontend graceful degradation**: `fetchExpiryCalendar()` silently fails — the old passive accumulation still works when the master is unavailable.

4. **`check_same_thread=False`**: Required for SQLite to be callable from FastAPI's async thread pool (the DB is created on the main thread but queried from worker threads).
