## Problem

Multiple distinct failure classes caused intelligence panels to show empty:

1. `IVRankCalculator` and `OITracker` were fully implemented but never instantiated
2. `SIGNAL_GENERATED` event was never published — scanner clusters/signal logs were dead
3. Max pain had NO backend implementation (only frontend JS)
4. Hints premium mapping read `premium` key but Fyers uses `ltp`

---

## Changes Made

### 1. Wire orphaned IVRankCalculator and OITracker

**File:** `src/shettyxtreme/terminal/api/app.py`

- Added instantiation of `IVRankCalculator` and `OITracker` in the lifespan function
- Stored on `app.state.iv_rank_calculator` and `app.state.oi_tracker`

### 2. Feed calculators from chain fetches

**File:** `src/shettyxtreme/terminal/api/intelligence_router.py`

- Added `_feed_options_calculators()` helper function that:
  - Feeds IV rank calculator with per-row IV data via `record_iv()`
  - Feeds OI tracker with full chain via `update_from_chain()`
- Called from both `GET /api/intelligence/options` endpoint and `prime_options_chain()`

### 3. Publish SIGNAL_GENERATED from pipeline

**File:** `src/shettyxtreme/intelligence/pipeline.py`

- In `_on_features()`, after publishing `SIGNAL_V2`, now also publishes `SIGNAL_GENERATED`
- Payload includes `symbol`, `direction`, `conviction`, `confidence`, `signal_id`
- This enables `ClusterDetector` and `LogCollector` to receive signal events

### 4. Fix hints premium mapping

**File:** `src/shettyxtreme/intelligence/hints/strategy_hints.py`

- Added `_row_premium()` helper in `_select_strike()` that checks `premium`, `ltp`, and `last_price` keys in order
- Updated `_usable()` validation to include `ltp` and `last_price` keys
- Updated filter condition to not drop rows that have `ltp`/`last_price` instead of `premium`

### 5. Implement backend max pain

**New file:** `src/shettyxtreme/options/max_pain.py`

- `compute_max_pain(contracts)` — pure function that computes max pain strike from option chain data
- Algorithm: iterates candidate strikes, sums CE/PE pain, returns strike with minimum total pain
- Handles `oi` and `open_interest` key variants

### 6. Expose max pain + analytics via API

**File:** `src/shettyxtreme/terminal/api/intelligence_router.py`

- Added `GET /api/intelligence/options-summary` endpoint
- Returns: `max_pain`, `pcr` (from OI tracker), `iv_rank_percent`, `iv_classification` (from IV rank calculator)
- Uses cached chain data when available, fetches on demand otherwise

**File:** `src/shettyxtreme/terminal/api/models.py`

- Added `OptionsSummaryResponse` pydantic model

## Architecture Notes

- `options/max_pain.py` is in the `options/` layer (intelligence boundary) — no external imports
- `IVRankCalculator` and `OITracker` are instantiated in the lifespan, stored on `app.state`, and fed passively from chain fetches
- `SIGNAL_GENERATED` is published from `IntelligencePipeline._on_features()` which is the same code path as `SIGNAL_V2` — no new subscribers or timers
- The max pain endpoint degrades gracefully: returns `None` when no chain data is available
