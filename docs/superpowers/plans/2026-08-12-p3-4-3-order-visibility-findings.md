# P3-4.3 Findings — Order Detail Visibility

**Date:** 2026-08-12 · **Status:** Investigation complete — no code changed

## TL;DR

The **proposal card already displays most order fields** (strike, CE/PE, expiry,
lots+qty, entry premium, SL/TGT, rationale) — but only **when the detail
exists**, and in production it usually doesn't:

- The production `ExecutionSignalBridge` is wired with the **default (minimal)
  hint builder**, which produces bare `NIFTY` + qty + MARKET + MIS and **no
  strike / expiry / option_type / SL / target / rationale**. The full-detail
  **chain hint builder already exists** (`make_chain_hint_builder` +
  `StrategyHints`) but is **never wired into `app.py`** — so the UI's "DEFAULT
  HINT" badge is the norm, and every field P3-4.3 wants is absent at the source.
- **Positions drop all trade context.** `PositionProjection` keeps only
  symbol/qty/avg/m2m/pnl; strike/expiry/CE-PE are re-derived at API time by
  parsing the Fyers symbol string, and SL/TGT/rationale/confidence exist **only
  on the `PendingApproval` record** — never carried to the position, never
  linked (no proposal_id/order_id on the position).
- **No order history / trade log exists anywhere**: no REST endpoint, no
  frontend component, no right-dock tab. The paper engine keeps `get_order_book()`
  in memory, but nothing routes it to the UI.
- The good news: `/api/intelligence/strategy-hint` **already returns the full
  order detail** (strike, expiry, option_type, lot_size, lots, entry_premium,
  stop_loss, target, confidence, rationale) — a working reference implementation
  of the exact payload P3-4.3 needs.

| Model | strike / expiry / option_type | stop_loss / target | rationale / confidence | lot_size |
|-------|-------------------------------|--------------------|------------------------|----------|
| `OrderRequest` (line 46) | ✅ `strike, expiry, option_type` | ❌ | ❌ | ✅ |

**Key asymmetry:** `OrderRequest` (the placement *request*) carries the option
identity, but the `Order` *record* (broker/paper state) does not — so even the
paper engine's in-memory order book cannot reconstruct what was traded. The
`Order` keeps a `tag` ("signal-v2") as the only provenance.

## 4. Proposal → Position flow — where detail is lost

```
SIGNAL_V2 ─► ExecutionSignalBridge._on_signal_v2 (signal_bridge.py:213)
              │  hint = self._hint_builder(values)        ← WHICH BUILDER?
              ▼
           ExecutionEngine.submit_signal(signal, hint)   (execution_engine.py:296)
              │  PendingApproval { signal, strategy_hint(dict), ... }
              ▼  (persisted to data/proposals.db — full hint dict survives restart)
           approve(approval_id)                          (execution_engine.py:319)
              │  _build_order(signal, hint) → OrderRequest  ← strike/expiry/option_type/lot_size carried
              │  risk check → validate → executor.place_order(order)
              ▼
           ModeRoutingExecutor → PaperTradingEngine.place_order (paper_trading.py:44)
              │  Order record: {symbol, side, order_type, quantity, price, tag="signal-v2"}
              │  ...NO strike/expiry/option_type/stop_loss/target/rationale...
              │  _fill_order → POSITION_CHANGED event (paper_trading.py:225):
              │    {symbol, side, quantity, price}   ← only these four keys
              ▼
           PositionProjection.on_position_update (projections.py:150)
              │  stores {symbol, exchange, quantity, buy_avg, net_quantity, m2m, pnl, product}
              ▼
           GET /api/execution/positions (execution_router.py:330)
              │  _enrich_position: parses symbol → strike/expiry/CE-PE
              │  _compute_position_greeks: IV cache + spot → greeks
              ▼
           PositionsRiskStrip.svelte (renders Symbol/Qty/Avg/M2M/P&L/ΔΓΘV only)
```

**Loss points:**

1. **Hint builder (production):** `app.py:479-483` wires `ExecutionSignalBridge`
   with only `instrument_master` → `make_default_hint_builder` → hint =
   `{symbol: "NIFTY", exchange: "NFO", quantity, lot_size, lots, price: None,
   order_type: MARKET, product: MIS, tag, hint_kind: "default"}`. **No
   strike/expiry/option_type/SL/target/rationale/confidence.** The chain builder
   (`signal_bridge.py:95` `make_chain_hint_builder` + `StrategyHints`) produces
   the full set but is never passed as `hint_builder=`.
2. **Response mapping:** even with the chain builder, `_proposal_response`
   (`execution_router.py:288-327`) maps only a fixed field list — `confidence`
   and `ev_after_cost` are in the hint dict but dropped.
3. **Order record:** `_build_order` → `OrderRequest` keeps option identity, but
   the broker/paper `Order` record and the `POSITION_CHANGED` event carry only
   `symbol/side/quantity/price` — **SL/TGT/rationale/confidence never cross the
   execution boundary.**
4. **No linkage:** a position cannot be traced back to its proposal/order —
   there is no `proposal_id`/`order_id`/`signal_id` on `PositionProjection` or
   `PositionResponse`. The only common key is the symbol string, and even that
   differs: proposal `symbol="NIFTY"` vs position Fyers symbol
   `NIFTY24AUG1224500CE`.
5. **SL/TGT are advisory only** — nothing enforces or monitors them post-fill
   (`PositionManager` exists but isn't wired to proposal SL/TGT; no exit-rule
   mechanism in the proposal payload).

## 6. Reusable code (build on these, don't reinvent)

1. **`make_chain_hint_builder`** — `execution/signal_bridge.py:95-175`. Already
   produces the complete hint: strike, expiry, option_type, stop_loss, target,
   rationale, confidence, ev_after_cost, lots, lot-rounded qty. Just needs
   wiring in `app.py` with chain + spot providers (`StrategyHints`).
2. **`StrategyHints`** — `intelligence/hints/strategy_hints.py`. Regime-gated
   strike selection via EV (`select_strike_by_ev`, `compute_signal_drift_ev` in
   `intelligence/options/options_intel.py`), 50%-SL / 2×-target defaults, full
   rationale string, `OptionLeg` (`intelligence/hints/option_leg.py`).
3. **`GET /api/intelligence/strategy-hint`** — `terminal/api/intelligence_router.py:488-526`.
   Returns the exact full-detail payload P3-4.3 wants (strike, expiry,
   option_type, lot_size, lots, entry_premium, stop_loss, target, confidence,
   rationale). Reference implementation for the enriched proposal response.
4. **`_enrich_position` / `_compute_position_greeks` / `update_iv_cache`** —
   `terminal/api/execution_router.py:47-166`. Already derives option identity
   from the symbol string and computes per-position greeks; the frontend just
   has to render the fields it already returns.
5. **`from_fyers` symbol parser** — `integration/fyers/symbols.py`. Parses
   underlying/strike/expiry/CE-PE from a Fyers instrument symbol.
6. **`PendingApproval.strategy_hint`** — `execution/execution_engine.py:52-64`,
   persisted to `data/proposals.db` (F-KNOW-002). Full hint detail round-trips
   the DB already; `_proposal_response` only needs to pass through
   `confidence`/`ev_after_cost` (+ add `underlying`/`strategy` to the hint dict
   if desired).
7. **`OrderRequest`** — already carries `strike/expiry/option_type/lot_size`;
   the pattern for extending the order/position records with the same fields is
   established (add SL/target/rationale as optional fields with defaults).
8. **`PaperTradingEngine.get_order_book()`** — `execution/paper_trading.py:92`.
   In-memory order list exists; a REST endpoint + frontend tab could expose it
   (extend `Order` with option identity + SL/target first, §3).
9. **DESIGN.md conventions** — Indian price colors (red up / green down), mono
   numerals, already used consistently in both components.

## 7. Proposed fix approach (algorithm, not code)

**A. Fix the source (biggest lever).** Wire `make_chain_hint_builder` into the
bridge in `app.py` with the existing chain/spot providers, so proposals are born
with full detail (strike, expiry, CE/PE, lot size, premium, SL, target,
rationale, confidence, EV). Without this, no amount of UI work helps — the data
never exists.

**B. Enrich the proposal payload end-to-end.** Extend `ProposalResponse` (and
the TS `Proposal` type) with `confidence`, `ev_after_cost`, `strategy`,
`underlying`, and optional `greeks` (reuse `_compute_position_greeks`-style
computation or add per-strike greeks at hint time). Update `_proposal_response`
to pass these through.

**C. Make the proposal card the full order ticket.** In `ProposalQueue.svelte`,
render the complete leg: underlying + strike + CE/PE + expiry as the headline
instrument line; labeled rows for lot size / lots / qty, entry premium, SL,
target, confidence, EV; full rationale (expandable, not 80-char truncated);
greeks when present. The confirm dialog already has the structure to copy.

**D. Link positions back to their plan.** Add `signal_id`/`order_id` to the
position projection (passed through the POSITION_CHANGED event from the fill),
and add SL/target/rationale/confidence to `PositionResponse` by joining the
approved `PendingApproval` hint (keyed by signal_id/order_id or symbol+side+ts).
Preserve SL/TGT in the `Order` record and the fill event so the chain survives.

**E. Render position identity + plan.** In `PositionsRiskStrip.svelte` and
`GreeksPanel.svelte`, render strike/expiry/CE-PE (data already in the API),
label entry premium for options, and show SL/TGT/rationale once the backend
supplies them.

**F. Add order history.** Expose the paper engine's order book (and eventually
broker orders) via a new `GET /api/execution/orders` endpoint, extend the
`Order` record with option identity + SL/target (see §3), and add an
Orders/History tab to `RightDockTabs` rendering filled/rejected/cancelled
orders with full leg detail.
