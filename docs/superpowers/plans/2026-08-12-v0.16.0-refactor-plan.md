- New system built alongside old system
- Feature-by-feature cutover (not big-bang)
- Rollback capability at each stage

### Testing Strategy

- Integration tests for new API endpoints
- E2E tests for critical user flows

## V2 API Implementation Details (2026-08-13)

### Summary
The v2 API namespace has been introduced to support incremental migration from v1. The implementation follows a parallel-run strategy where v1 and v2 coexist.

### Files Created
- `src/shettyxtreme/terminal/api/v2/__init__.py` — v2 router with proof-of-concept endpoints
- `src/shettyxtreme/terminal/api/v2/models.py` — V2 Pydantic response models

### V2 Endpoints Implemented

| Endpoint | Method | Description | V1 Equivalent |
|----------|--------|-------------|---------------|
| `/api/v2/version` | GET | API version and migration metadata | New |
| `/api/v2/watchlist` | GET | Enriched watchlist with v2 metadata | `GET /api/watchlist` |
| `/api/v2/options/chain` | GET | Options chain with aggregate analytics | `GET /api/intelligence/options` |

### V2 Model Enhancements

**WatchlistItemV2** (extends v1):
- Added: `instrument_type`, `bid`, `ask`, `oi`, `is_tradable`
- All v1 fields preserved for backward compatibility

**OptionsChainResponseV2** (extends v1):
- Added: `spot` (underlying price), `max_pain`, `pcr`, `iv_rank_percent`
- Contract-level: `spot_distance_pct` (% from spot to strike)
- All v1 contract fields preserved

### Migration Strategy
1. **Parallel run**: v1 and v2 coexist indefinitely
2. **Incremental adoption**: Clients migrate endpoint-by-endpoint
3. **Backward compatible**: v2 responses are superset of v1
4. **No breaking changes**: v1 endpoints remain unchanged

### Frontend Integration
- Added TypeScript types: `WatchlistItemV2`, `OptionsChainItemV2`, `OptionsChainResponseV2`, `APIVersionInfo`
- Added API functions: `getAPIVersion()`, `getWatchlistV2()`, `getOptionsChainV2()`
- v1 functions remain unchanged (backward compatibility)
