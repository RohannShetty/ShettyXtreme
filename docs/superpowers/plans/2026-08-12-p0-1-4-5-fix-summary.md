## Root Causes Fixed

### P0-1.4: Proposals Carry No Leg Data
- `default_hint_builder` hardcoded `symbol="NIFTY"`, `quantity=75`, `exchange="NFO"` — no strike, expiry, CE/PE, lot size
- `StrategyHints` (which picks strike/premium/EV) existed but was never wired to the proposal flow
- No `OptionLeg` model existed anywhere in the codebase
- `OrderRequest` had no strike/expiry/option_type fields
- API response models (`ProposalResponse`, TS `Proposal`) carried no leg fields
- Frontend rendered bare "NIFTY BUY" with no leg context

### P0-1.5: Quantity Hardcoded to 75 (Now Wrong — NIFTY Lot = 65)
- `_DEFAULT_QUANTITY = 75` in `signal_bridge.py:35`
- `base_quantity: int = 75` in `strategy_hints.py:54`
- `lot_size: int = 75` in `cost_model.py:42`
- `LOT_SIZE = 75` in `walkforward.py:15`
- No `get_lot_size()` helper on `FyersInstrumentMaster`
- No `lot_size × lots` computation anywhere in the pipeline

## Edge Cases Handled

1. **No instrument_master available**: `default_hint_builder` returns `quantity=None`; proposals show raw quantity without lot breakdown; `_build_order` uses `int(hint.get("quantity") or 0)` → 0 → validator rejects (safe)
2. **Unknown symbol**: `get_lot_size()` returns `None` → hint builder skips proposal (logged)
3. **Chain rows with `ltp`/`last_price`** instead of `premium`: `_select_strike` checks all three keys
4. **Lot-rounded quantity**: `OptionLeg.qty = lots * lot_size`; `_build_order` passes through to `OrderRequest.quantity`
5. **Backward compatibility**: all new fields are optional with `None` defaults; existing code paths unaffected
