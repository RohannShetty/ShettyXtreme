# P0-1.3 Fix Summary — Paper Trading Margin = 0

**Date:** 2026-08-12 · **Status:** Fix applied

## Problem

In PAPER mode, every order approval was rejected with:
`pre-execution risk check rejected: insufficient margin: available=0.00 < required=5000.00`

Root cause: `PaperTradingEngine` held ₹10L capital but never exposed it to the risk chain. The `_portfolio_provider` in `app.py` read `margin_available` from `RiskProjection`, which defaulted to `None` in PAPER mode (no broker poller), and coerced `None → 0.0`, causing `MarginFilter` to reject every order.

## Changes Made

### 1. `configs/default.yaml`
- Added `paper_trading_margin: 1000000` (₹10L, matching existing `PaperTradingEngine` default capital)

### 2. `src/shettyxtreme/core/config/config_manager.py`
- Added `"paper_trading_margin": (int, float, type(None))` to `_SCHEMA` dict — accepts YAML int or float
- Added `paper_trading_margin: float | None = None` to the `Config` dataclass
- Added `SHETTY_PAPER_TRADING_MARGIN` env var override in `_load_env_overrides` with float coercion

### 3. `src/shettyxtreme/execution/paper_trading.py`
- Imported `Portfolio` from `intelligence.risk.risk_engine`
- Added margin accounting in `_fill_order`: decrements `_capital` on BUY fills (notional = quantity × fill_price), restores on SELL fills
- Added `get_portfolio() -> Portfolio` method that returns a `Portfolio` dataclass reflecting current paper capital, open position notional, and daily P&L

### 4. `src/shettyxtreme/terminal/api/app.py`
- Imported `ConfigManager` from `core.config.config_manager`
- In `lifespan`: loads config from `configs/default.yaml` and passes `config.paper_trading_margin or 1_000_000.0` as `initial_capital` to `PaperTradingEngine`
- In `_portfolio_provider`: when `margin_available` is `None` and current mode is `PAPER`, falls back to `paper_engine.get_portfolio().available_margin`

### 5. Tests Added

**`tests/execution/test_paper_trading.py`** (3 new tests):
- `test_paper_engine_get_portfolio_initial_capital` — verifies `available_margin == initial_capital` at start
- `test_paper_engine_buy_fill_reduces_margin` — verifies available_margin decreases by notional after BUY
- `test_paper_engine_sell_restores_margin` — verifies margin restored after BUY+SELL cycle

**`tests/wave2/test_risk_engine.py`** (1 new test):
- `test_margin_filter_allows_paper_funded_portfolio` — with `Portfolio(available_margin=1_000_000)`, entry is allowed

**`tests/wave5/test_execution_engine.py`** (1 new test):
- `test_paper_mode_approve_succeeds_with_funded_portfolio` — end-to-end: paper engine provides portfolio → `ExecutionEngine.approve()` succeeds

## Data Flow After Fix

```
configs/default.yaml  →  ConfigManager.paper_trading_margin  →  PaperTradingEngine(capital)
                                                                       ↓
ExecutionEngine.approve()  →  _portfolio_provider()  →  paper_engine.get_portfolio()
                                                              ↓
                                              Portfolio(available_margin=₹10L)
                                                              ↓
                                                    MarginFilter.check()  →  ALLOW
```

In PAPER mode: `_portfolio_provider` detects `margin_available is None` + mode is `PAPER`, reads `paper_engine.get_portfolio().available_margin` (live, always fresh). LIVE mode continues using the broker poller unchanged.
